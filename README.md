# AI-buddy: ИИ-наставник для стажёров

Прототип для кейса Hack&Change 2026 (Авито). Помощник отвечает стажёру по базе знаний команды, оформляет рутинные действия (отгул, доступы) и **не выдумывает ответы**: если уверенного ответа нет, вопрос уходит наставнику в дайджест. Наставник отвечает один раз, ответ получают все, кто спросил то же самое, и он остаётся в базе знаний для следующих стажёров.

> Все данные синтетические. Тестовые инструкции в базе знаний придуманы для прототипа и **не являются регламентами Авито**.

## Быстрый запуск (Docker)

```bash
cp .env.example .env     # необязательно, все настройки имеют значения по умолчанию
docker compose up --build
```

Открой http://localhost:8080 . Docker соберёт интерфейс (React + TypeScript) и запустит бэкенд (Flask) в одном контейнере. Данные лежат в томе `buddy-data`, тестовые данные создаются при первом старте.

## Проверка за 3 минуты

1. Войди как `intern1`. В чате напиши: **«Как оформить отгул?»**. Придёт ответ из базы знаний с пометкой источника.
2. Напиши: **«Оформи отгул с 20 по 22 ноября, причина: личные дела»**. Появится карточка. Нажми «Подтвердить»: в чате номер заявки `ABS-…`, он же в списке справа.
3. Напиши: **«Запроси доступ к VPN»** и подтверди. Шаг «Запросить доступ к VPN» в чек-листе станет «ждёт согласования».
4. Напиши: **«Где взять пропуск в офис?»**. Помощник честно скажет, что не знает, и передаст вопрос наставнику.
5. Выйди, войди как `intern2`, спроси: **«пропуск в офис где взять»**.
6. Войди как `mentor1`. В дайджесте **одна строка «Спросили: 2»**. Ответь один раз. Здесь же можно одобрить отгул и выдать доступ.
7. Войди снова как `intern1`: ответ наставника, решение по отгулу и выданный доступ уже в чате. Повтори вопрос про пропуск: ответ приходит мгновенно, без наставника. У наставника выросли метрики пользы.

## Запуск без Docker

Нужны Python 3.12+ и (для интерфейса) Node 22+.

```bash
# интерфейс
cd frontend
npm install
npm run build            # соберёт frontend/dist

# бэкенд, он же отдаёт интерфейс
cd ../backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
STATIC_DIR=../frontend/dist python wsgi.py     # http://localhost:5000
```

В архиве уже лежит готовая сборка `frontend/dist`, поэтому шаг с npm можно пропустить.

## Тесты и покрытие

```bash
# через Docker: тесты + отчёт, порог 80%
docker compose --profile test run --rm tests

# локально, без внешних библиотек (Python 3.12+)
cd backend
python tools/coverage_report.py --fail-under 80 --html ../docs/coverage/html --text ../docs/coverage/coverage.txt

# то же обычным pytest-cov (если установлен)
python -m pytest --cov=app --cov-report=term-missing --cov-fail-under=80
```

Что считается: строки прикладного кода в `backend/app/` (тесты и зависимости не входят). Результат прогона: **108 тестов, покрытие строк 99,4%** (отчёт в `docs/coverage/`, HTML: `docs/coverage/html/index.html`). Скрипт `tools/coverage_report.py` написан без зависимостей на `sys.monitoring`, потому что он должен работать в любом окружении; он считает строки, не ветвления.

## Что умеет прототип

- **Вопросы и обучение базы.** Ответ из базы знаний или передача наставнику; дайджест с группировкой одинаковых вопросов; ответ наставника попадает в базу и в чат каждого, кто спрашивал.
- **Отгул.** Помощник понимает даты и причину в обычной речи, показывает карточку, после подтверждения вызывает инструмент «сервис отсутствий» (имитация), показывает номер заявки и сохраняет её. Руководитель решает заявку, решение приходит стажёру в чат.
- **Доступы и путь адаптации.** Статусы доступов, запрос доступа через чат, чек-лист из 4 этапов и 12 шагов, шаги про доступы закрываются сами, «что дальше?» называет следующий шаг.
- **Права.** Роли стажёр и наставник, наставник видит только своих стажёров, закрытые записи наставника стажёру не показываются, параметры действий хранятся на сервере.
- **Платформа.** Feature flags, события продукта (имитация Clickstream), дайджест по расписанию (имитация ИИ-крона), необязательный LLM.

Подробности поведения: [specs/](specs/README.md). Архитектура и переход к корпоративному стеку: [docs/architecture.md](docs/architecture.md).

## LLM и внешние сервисы

Для работы **ключи и внешние API не нужны**: по умолчанию ответы берутся из базы знаний. LLM подключается переменными окружения (см. `.env.example`): `LLM_PROVIDER` (`anthropic` или `openai`, второй подходит для любого OpenAI-совместимого сервера через `LLM_BASE_URL`), `LLM_MODEL`, `LLM_API_KEY`, `LLM_TIMEOUT`.

С включённым LLM он формулирует ответ только по найденным записям базы знаний; если ответа в них нет, возвращает `NO_ANSWER`, и вопрос уходит наставнику. Любой сбой или таймаут не ломает чат, ответ берётся из базы знаний. Интерфейс при этом не блокируется: пока идёт запрос, показывается индикатор набора. Флаг `llm_answers` отключает LLM без перезапуска (кабинет наставника, «Настройки»). Вызов с реальным ключом в этой поставке не проверялся, проверен код и обработка ошибок на подмене сети.

Дайджест по расписанию: `python -m app.cron` или `POST /api/internal/cron/digest` с заголовком `X-Cron-Token` (задаётся переменной `CRON_TOKEN`).

## Ограничения прототипа

- Авторизация и роли: заглушка. В Авито используются корпоративные.
- Сервисы отсутствий и доступов: имитация на SQLite, интерфейс инструментов совпадает с MCP-подходом.
- Поиск по базе знаний: по словам (грубый стемминг), в проде нужен семантический поиск.
- Чек-лист построен по трём стадиям из описания кейса; сам чек-лист Авито из таблицы кейса не использовался, потому что таблица недоступна из окружения, где собирался прототип.
- Docker-сборка в окружении разработки не запускалась (нет Docker и сети). Проверены: все тесты, сборка интерфейса через esbuild, работа приложения с этим интерфейсом в браузере (Chromium) и видео записано с этой сборки.
