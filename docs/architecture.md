# Архитектура AI-buddy

## Обзор

Прототип состоит из одного Docker-образа:

- **Frontend** — React-интерфейс (чат, чек-лист, кабинет наставника)
- **Backend** — Flask + SQLite (API, бизнес-логика, база знаний)

В продакшене Flask заменяется на внутренние сервисы Авито, SQLite — на PostgreSQL, а авторизация — на корпоративный SSO.

## Потоки

### 1. Вопрос стажёра → ответ / эскалация

```
Стажёр → POST /api/chat
  → intents.detect()          # действие или KB?
  → kb.top_matches()          # поиск по базе знаний (стемминг)
  → [опционально] llm.answer  # формулировка строго по найденным фрагментам
  → если score < KB_MIN_SCORE → questions.status = pending → дайджест наставника
  → иначе → ответ в чат + mark_used
```

### 2. Действие (отгул / доступ)

```
Стажёр пишет «Оформи отгул…»
  → proposal-карточка в чате (параметры на сервере)
  → подтверждение → mcp_tools.call_tool()
  → результат в чат + история
```

Подмена параметров невозможна: они хранятся в `messages.payload`.

### 3. Learning loop

```
Несколько стажёров спрашивают одно и то же
  → группировка по signature (порядок-независимый стемминг)
  → наставник отвечает один раз
  → ответ уходит всем + попадает в kb_entries
  → следующий стажёр получает автоответ
```

## Роли и изоляция

| Роль | Видит |
|------|--------|
| intern | свой чат, чек-лист, свои заявки |
| mentor | дайджест своих стажёров, метрики, заявки на согласование |

Audience у записей KB: `all` | `mentor`.

## Внедрение в Авито

| Прототип | Продакшен |
|----------|-----------|
| SQLite | PostgreSQL / внутренние БД |
| Bearer-токен | Корпоративный SSO + роли |
| mcp_tools (заглушки) | Реальные MCP-сервисы отсутствий и доступов |
| Clickstream-таблица | Kafka → Grafana |
| Feature flags в SQLite | Корпоративные флаги |
| LLM через HTTP | Внутренний LLM-шлюз |
