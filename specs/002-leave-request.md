# 002. Отгул через имитацию сервиса отсутствий

## Цель
Стажёр не знает порядка оформления и не хочет отвлекать руководителя. Помощник объясняет процедуру и сам оформляет заявку.

## Инструмент (MCP-подобный интерфейс)
`create_leave_request(start_date, end_date, reason?)` — см. `GET /api/tools`.

## Поведение (`POST /api/leave-requests`)
1. Доступно только роли `intern` (иначе 403).
2. Даты в формате `ГГГГ-ММ-ДД`, иначе 400.
3. `end_date >= start_date`; `start_date` не в прошлом; длительность не больше `MAX_LEAVE_DAYS` (14).
4. Причина до 200 символов.
5. Пересечение с другой заявкой стажёра (кроме отклонённых): 409.
6. Успех: заявка сохраняется со статусом `submitted`, сервис возвращает `external_id` вида `ABS-000123`. Помощник показывает его и сохраняет (это и есть «выполненное действие»).

**Решение руководителя (`POST /api/leave-requests/<id>/decision`)**
- Только наставник/руководитель этого стажёра. `approve` или `reject`.
- Решение по уже решённой заявке: 409. Чужая заявка: 404.

**Видимость**
- Стажёр видит только свои заявки; наставник — заявки своих стажёров.

## Критерии приёмки
- [x] Результат сервиса (`external_id`, статус) возвращается и сохраняется.
- [x] Ошибки валидации понятны человеку (сообщение на русском).
- [x] Стажёр не видит чужие заявки.
