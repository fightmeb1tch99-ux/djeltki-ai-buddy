# 003. Доступы и чек-лист адаптации

## Доступы
- `GET /api/access` — статусы доступов стажёра (`requested` / `granted`) и список систем, которые можно запросить.
- `POST /api/access {system}` — создаёт заявку. Повторный запрос той же системы ничего не дублирует (`created: false`). Неизвестная система: 400.
- `GET /api/access/pending` — наставнику: заявки его стажёров, ожидающие выдачи.
- `POST /api/access/<id>/grant` — только наставник этого стажёра; стажёр получает сообщение в чат.

## Чек-лист адаптации
4 этапа и 12 шагов по трём стадиям из описания кейса: знакомство с командой, рабочие инструменты и доступы, первые задачи, плюс итоги.

- `GET /api/stages` — этапы с шагами, статусом этапа (`todo` / `in_progress` / `done`), `done_count`, `progress_percent` и `next_step`.
- Статус шага: `done`, если отмечен стажёром или (для шага со ссылкой `access:<Система>`) доступ выдан; `in_progress`, если доступ запрошен и ждёт; иначе `todo`.
- `next_step` — первый шаг, который стажёр может сделать сам. Если остались только шаги в ожидании согласования, возвращается один из них с `waiting: true`. Все шаги выполнены: `null`.
- `PATCH /api/tasks/<id> {done: bool}`: отметить или снять шаг. Шаг со ссылкой на доступ закрывается только выдачей доступа (409). Неизвестный шаг: 404, не булево `done`: 400.
- `GET /api/mentor/interns` — прогресс и следующий шаг каждого стажёра наставника.

## Критерии приёмки
- [x] Стажёр всегда видит прогресс и следующий шаг.
- [x] Запрос доступа сразу двигает связанный шаг, выдача закрывает его.
- [x] Наставник видит прогресс только своих стажёров.
