# 004. Права и безопасность

## Модель
Авторизация и роли в Авито уже существуют, поэтому в прототипе это заглушка: `POST /api/login` выдаёт токен, роль берётся из пользователя (`intern`, `mentor`). В проде заменяется на корпоративную авторизацию, контракт `Authorization: Bearer <token>` остаётся.

## Правила
1. Без токена любой `/api/*` кроме `/api/health` и `/api/login`: 401.
2. Эндпоинты стажёра недоступны наставнику и наоборот: 403.
3. Наставник видит и меняет только данные **своих** стажёров (вопросы, заявки, прогресс, метрики). Чужое: 404.
4. Записи базы знаний с `audience = mentor` не попадают в ответы стажёрам.
5. Действия через инструменты проверяют роль внутри самого инструмента, а не только в маршруте.
6. Пароли хранятся хэшами; в репозитории только тестовые учётные записи. Токен живёт `TOKEN_TTL_HOURS` (12), `POST /api/logout` закрывает его.
7. Параметры действий хранятся на сервере в карточке; подтвердить можно только свою карточку (см. 005).
8. Чувствительные персональные данные и финансовые операции вне области прототипа.

## Критерии приёмки
- [x] Стажёр не получает ответ из закрытой записи наставника.
- [x] Стажёр не видит чужие заявки.
- [x] Наставник не может создать отгул от имени стажёра.
